## 一、测试目标

在正式开发第一个 ARG 前，用一个 6 页微型解谜游戏验证：

1. 搜索框关键词推进玩法是否可行
2. 伪装真实网站的手感
3. iOS/安卓/桌面三端适配
4. file:// 免服务器运行
5. 开发流程（工作流六阶段的迷你版）

## 二、Demo 内容

**故事**：玩家是顾晴，在「福安家常菜馆」官网搜索关键词，一步步发现弟弟顾铭失踪前留下的纸条和「好运席」民俗秘密。

**页面链**（6页）：
```
首页(1) → 顾铭(2) → 纸条(3) → 符(4) → 好运席(5) → 刘师傅(6·反转)
```

**核心机制**：
- 搜索框输入关键词触发隐藏页面
- 右下角数字圆点 = 进度标记
- 首页失物招领卡片 = 新手引导（显眼但不明显）
- 结尾身份反转：「你……不是顾晴吗？」

## 四、测试学到的东西（用于正式游戏）

### 玩法层面
1. **搜索框解谜很直观**——玩家天生会去搜看到的名字
2. **进度数字是重要反馈**——每页右下角的数字让玩家知道「还有多少」
3. **「置顶失物招领」是好引导**——自然、不突兀、有效
4. **信息碎片要留钩子**——每页结尾都要暗示下一个关键词

### 技术层面
1. **单文件架构对ARG非常合适**——便于分享、便于托管、永不挂
2. **伪装网站要「脏一点」**——真实网站有乱码、有浏览数1、有年代感
3. **移动端输入框必须16px**——否则iOS自动缩放毁掉沉浸感
4. **触控目标≥44-48px**——手机玩家不会点错

### 待改进（正式游戏注意）
1. 关键词匹配目前是双向模糊匹配，正式版要考虑「错误提示」的设计
2. 正式版需要多结局分支，不只线性6页
3. 需要手机端测试真机效果（无头截图不能替代）
4. 音效/背景音乐是氛围利器，Demo未做
